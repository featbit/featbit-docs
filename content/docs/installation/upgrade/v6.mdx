This page records upgrades between stable v6 releases. Read the [general upgrade guidelines](/installation/upgrade/general-guidelines) before upgrading. If you are moving from v5 to v6, follow [Upgrade to v6](/installation/upgrade/upgrade-to-v6) first, then apply the relevant entries below.

## v6.1.1

**Upgrade status:** You can upgrade directly from `6.1.0` by updating the FeatBit application images to `6.1.1`. No additional database migration is required. When upgrading from `6.0.0`, `6.0.1`, or `6.0.2`, apply the database migration described under [v6.1.0](#v610) before starting the `6.1.1` application services.

**Release:** [v6.1.1 on GitHub](https://github.com/featbit/featbit/releases/tag/6.1.1).

**What's changed:** Fixed SSO account setup, PostgreSQL user-name loading, and the per-flag insights setting in SDK synchronization and evaluation API payloads. Improved variation change reviews, audit logs, SSO configuration, and Evaluation Server authentication and performance.

**Compatibility notes:**

- Evaluation Server HTTP SDK sync endpoints require the matching client or server secret. Invalid secrets return `401`, disallowed secret types return `403`, and unavailable secret verification returns `503`.
- Successful secret lookups are cached locally for 30 seconds for HTTP and streaming authentication. Secret revocation may take up to 30 seconds plus an in-flight lookup to affect new authentication attempts. Cache hits do not extend expiration.
- Client hostname resolution is disabled by default. Set `Streaming__TrackClientHostName=true` if you need hostname resolution for detailed logging.

## v6.1.0

**Upgrade status:** Database migration is required when upgrading from `6.0.0`, `6.0.1`, or `6.0.2`. Apply the migration for your database before updating the FeatBit application images to `6.1.0`.

**Release:** [v6.1.0 on GitHub](https://github.com/featbit/featbit/releases/tag/6.1.0).

**What's changed:** Added per-flag insight collection controls, IAM audit logs, and a dedicated SDK secret-view permission, alongside API documentation improvements and fixes. See the release notes for details and compatibility changes.

**Data migration:** Run the script for your database:

| Database | Script | Changes made |
| --- | --- | --- |
| PostgreSQL | [v6.1.0.sql](https://github.com/featbit/featbit/blob/6.1.0/infra/postgresql/docker-entrypoint-initdb.d/v6.1.0.sql) | Adds the per-flag insights setting, updates secret-view permissions, and updates audit-log structure, historical data, and indexes. |
| MongoDB | [v6.1.0.js](https://github.com/featbit/featbit/blob/6.1.0/infra/mongodb/docker-entrypoint-initdb.d/v6.1.0.js) | Updates secret-view permissions, backfills historical audit-log data, and updates audit-log indexes. |

## v6.0.2

**Upgrade status:** You can upgrade directly from `6.0.0` or `6.0.1` by updating the FeatBit application images to `6.0.2`. No database migration is required.

**Release:** [v6.0.2 on GitHub](https://github.com/featbit/featbit/releases/tag/6.0.2).

**What's changed:** Fixed an issue where new users could get stuck after signing in with SSO. Affected users can sign in again to complete their account setup.

## v6.0.1

**Upgrade status:** No additional upgrade steps when upgrading from `6.0.0`. Update the FeatBit application images to `6.0.1` using your existing deployment process. No database migration is required.

**Release:** [v6.0.1 on GitHub](https://github.com/featbit/featbit/releases/tag/6.0.1).

**What's changed:** Fixed Evaluation Server rejecting non-empty custom string variation IDs that are not GUIDs as malformed data. GUID variation IDs remain supported.

**Who is affected:** Deployments with feature flags that use custom, non-GUID variation IDs should upgrade to restore normal operation. Flags created through the UI use GUID variation IDs and are unaffected, as are custom IDs supplied through the API that are valid GUIDs.
